# A shared domain kernel is the one sanctioned exception to slice isolation

The DDD building blocks every slice needs — the `IDomainEvent` marker and the `AggregateRoot` base that records domain events — live in one `Shared/Podkop.Shared.Domain` project that every slice's Domain project references, rather than being hand-rolled per slice. ADR 0003 says features never reference each other's internals; a shared kernel is not that, but it is close enough to need saying out loud. Two byte-identical `IDomainEvent` markers and two copies of the same `_domainEvents` list had already appeared across Findings and FindingComments, and slice-local event types make generic event infrastructure impossible — an outbox interceptor cannot handle "any domain event" when every slice declares its own unrelated marker. Decided in [#93](https://github.com/WojtekF/Podkop/issues/93).

## Consequences

- **The admission test is semantic emptiness.** A type belongs in the kernel only if it carries no feature vocabulary: it must be something two unrelated slices would each invent identically, with nothing of either slice's domain in it. `IDomainEvent`, `AggregateRoot`, and (when a slice first needs one) `ValueObject` pass. Anything naming a finding, comment, user, report, tag, or vote fails — including seemingly generic types like `Author`, `VoteDirection`, or a shared `Id`. When in doubt the type stays in its slice; duplication across two slices is cheaper than a kernel that quietly becomes a god-model every slice is coupled through.
- **Dependency direction.** `Podkop.Shared.Domain` references nothing — not MediatR, not EF Core, no other Podkop project. Every slice's Domain project may reference it; nothing else in the kernel's direction ever reverses.
- **`Podkop.*.Contracts` projects stay kernel-free.** Contract events remain primitive-only records, as ADR 0003 requires. A contract event typed against a kernel abstraction would couple consuming slices to the producer's domain shape through the back door, which is exactly what the Contracts layer exists to prevent. Domain events implement `IDomainEvent` and stay inside their slice; Infrastructure translates them into primitive contract events after persistence.
- **The kernel is a change-amplifier, so it stays small.** Every edit to `AggregateRoot` is an edit to every aggregate in the codebase. That is the price of removing the duplication, and it is only worth paying for types that genuinely never change. Growth is by ticket and by evidence of real duplication — never speculatively.
- **What the kernel does *not* own, for now.** Aggregate identity is deliberately excluded: both current aggregates carry a `Guid Id`, but strongly-typed ids ([#95](https://github.com/WojtekF/Podkop/issues/95)) will change that shape, and pulling identity up before that lands means moving it twice. `ValueObject` waits until a slice needs one.
- **Migrating the existing aggregates changes their public surface slightly.** `Finding` gains a public `ClearDomainEvents()` it never had — harmless, and the symmetry is what makes generic draining possible — and `Comment.RaiseCommentAdded()` collapses into a `Raise(...)` call.
- **`/Shared/` now holds three projects with different standing.** `Podkop.Shared.Infrastructure` (sample-data vocabulary) and `Podkop.Shared.Testing` (the Testcontainers fixture, ADR 0010) are conveniences with no semantic weight. `Podkop.Shared.Domain` is the first shared project that shapes the model, and the only one this ADR sanctions; a future shared project holding domain meaning needs its own decision record.
- **What this unlocks.** One EF Core interceptor can drain and publish domain events for every slice generically ([#94](https://github.com/WojtekF/Podkop/issues/94)) — today each slice's `EfUnitOfWork` does it by hand, and `Findings` does not do it at all, so `FindingPromoted` is raised and never consumed.
